# @puddleworks/obsidian-task-scan

Find the tasks in an Obsidian vault that a swamp extension could do.

List the open tasks in an Obsidian vault, leaving out templates and daily notes,
and ask Jev whether a swamp extension could do each one. Search the extension
registry for each one it could, and log each one no extension covers in Capture
as a draft request.

## For the user

The app runs on a schedule. You can also run it now from puddle with the form below.

| What to enter | Kind | Default |
|---|---|---|
| Subfolder of the vault to scan, relative to the vault root. Empty scans the whole vault. | string | empty |

**You get:** every open task with its file and line, marked `candidate` (Jev says
it is worth a reusable extension, with at least 0.5 confidence), `not_candidate`
(a one-off job or one that needs a person),
`withheld` (it looks like it holds a secret, so it was never sent to Jev) or
`unclassified` (Jev could not be reached, or turned the request away; the next
run tries again).

Each task also has an outcome:

- `logged`: a draft request in Capture, with its link. A task is logged once,
  ever: running again gives back the same request.
- `matched`: Jev picked an extension the registry search found as already
  doing it, with at least 0.5 confidence. Its name is given; nothing is logged.
- `skipped`: not a candidate, withheld, unclassified, or the run is a preview.
- `failed`: the registry search, Jev's pick or Capture failed, so nothing was
  logged for it. The next run tries again.

Install it in the swamp repo that holds Capture: the workflow logs requests by
calling `create_request` on a `@puddleworks/capture/requests` behavior in the
same repo. This also pulls `@swamp/typesafe-ai`, `@puddleworks/capture` and the
workflow `@puddleworks/obsidian-task-scan`:

```bash
swamp extension pull @puddleworks/obsidian-task-scan
```

Create the model instances the workflow runs. `excludeFolders` is optional and
defaults to `["Templates"]`; daily notes (`YYYY-MM-DD.md`) are always left out.
`batchSize` is optional and defaults to 150: the workflow asks Jev about that
many tasks per request, one request at a time, because Jev's free tier turns
away requests of about 800 questions. A request that fails leaves only its own
tasks unclassified.

```bash
swamp model create @puddleworks/obsidian-task-scan obsidian-task-scan-model \
  --global-arg vaultPath=/path/to/your/vault
swamp vault create local_encryption typesafe
swamp vault put typesafe TYPESAFE_API_KEY    # prompts for the key
swamp model create @swamp/typesafe-ai jev \
  --global-arg 'apiKey=${{ vault.get("typesafe", "TYPESAFE_API_KEY") }}' \
  --global-arg baseUrl=https://opencode.ai/zen \
  --global-arg model=jev-1.13-free
```

The text, note path and nearest heading of every task that is not withheld are
sent to the Jev endpoint. Up to four words of each candidate's text are sent to
the swamp extension registry as a search. A withheld task is never sent, and
neither is a heading that looks like it holds a secret.

Logging settings, all optional:

- `logAs` — the email the Capture requests are logged for; they must be in
  Capture's people list. Empty (the default) logs nothing: the run is a
  preview, and each task a live run would log is `skipped` with `wouldLog`.
- `captureModel` — the Capture behavior's name (default `capture`).
- `captureUrl` — where Capture serves request pages (default
  `http://127.0.0.1:3002`), for the links in the result.
- `matchThreshold` — least confidence in Jev's pick of an extension for a
  candidate to count as covered (default 0.5).

Preview first, then go live:

```bash
swamp workflow run @puddleworks/obsidian-task-scan
swamp data query 'behavior("obsidian-task-scan-model") && name == "logged"' --select content --json
swamp model edit obsidian-task-scan-model    # under globalArguments, set logAs: you@example.com
```

Run it:

```bash
swamp workflow run @puddleworks/obsidian-task-scan
```

Read the result:

```bash
swamp data query 'behavior("obsidian-task-scan-model") && name == "logged"' --select content --json
```

Each item has `path` (relative to the vault), `line` (1-based), trimmed `text`,
`heading` (the nearest heading above it, sent to Jev as context), `id` (stable
across runs: from the path and text), `classification`, for classified tasks
`choice` and `confidence`, and `outcome`, with `request` (`id`, `number`,
`url`) when logged, `extension` when matched, and `reason` when skipped or
failed. `counts` totals each outcome. The request's idempotency key is
`obsidian-task-scan:<id>`, so a task is logged once however often it runs.
Capture holds the key per person, so keep `logAs` the same: changing it logs
each task again, for the new person.
`matched` holds what the registry search found for each candidate.

A run calls Capture at most 90 times; any more candidates wait for the next
run, which reuses what the last one logged.

Schedule it:

```bash
swamp workflow trigger set @puddleworks/obsidian-task-scan --schedule "0 8 * * 1"
swamp workflow trigger get @puddleworks/obsidian-task-scan
```

This example runs Mondays at 08:00. Scheduled runs need `swamp serve`; add `--input folder=Projects` to the trigger set command to limit them to a subfolder.
